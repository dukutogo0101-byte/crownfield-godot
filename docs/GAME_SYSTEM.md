# CROWNFIELD ゲームシステム（実装の説明）

更新日: 2026-10-15。共同開発者はこの文書から読み始める。

この文書は `core/simulation.gd`、`data/rulesets/playable_experimental.json`、`ui/game.gd` の**現在の実装**を説明する。原作ロードモナークの確定仕様を主張する文書ではない。原作の調査仕様は `SPEC_CANONICAL_JA.md` と `RULE_STATUS.csv` に分離してある。矛盾があれば実装を確認し、この文書を更新する。`distributions/` の元ZIP・APKは復旧時点の旧版で、最新ソースではない。

## プレイヤーの目的と基本ループ

プレイヤーは青国（team 0）を操作する。村の人口を増やす → 領地を広げる → 部隊を出す → 住居を建設する／味方と合流する → 敵の部隊・村・王へ進軍する、というリアルタイム戦略ゲーム。現在は独自マップ「Four Rivers」1面のみ。

- 敵3国の王を倒し、自国だけが生存すると勝利。
- 自国の王が倒れると敗北。
- 自国が生存していても600日（3600 tick）で制限時間切れになると敗北。
- 王による敵王の撃破だけが資産接収になる。通常部隊による王撃破では敗れた国の資産は消滅する。

## 地図と初期配置

40 × 26の格子。位置IDは `y * w + x`、座標は0始まり。移動・戦闘接触・橋等の作業位置は上下左右の4方向、村の周囲と村同士の建設間隔は斜めを含む8方向を使う。

| team | 名前 | 操作 | 城の位置ID | 初期資金 | 税率 |
|---|---|---|---:|---:|---:|
| 0 | Azure | プレイヤー | 164 | 800 | 10% |
| 1 | Crimson | CPU | 194 | 800 | 10% |
| 2 | Jade | CPU | 874 | 800 | 10% |
| 3 | Amber | CPU | 844 | 800 | 10% |

各国に人口128の村2つ、兵力96の部隊2つ、兵力448の王1人を初期配置する。

| terrain | 地形 | 通行 |
|---:|---|---|
| 0 | さら地 | 柵がなければ通行可能 |
| 1 | 荒れ地 | 柵がなければ通行可能。開墾で0になる |
| 2 | 水面 | 橋耐久が1以上で通行可能 |
| 3 | 洞窟 | 通行不可。封鎖で0になる |

所有者 `owner` は中立=-1、国=0〜3。歩兵がさら地へ移動すると、そのマスの所有者が自国になる。敵村へ進入すると村を破壊する。柵があるマスは橋の有無にかかわらず通行できない。

## 時間と処理順

整数tickで決定論的に進行する。乱数は現在使用していない。UIの速度や実時間はコアの計算式を変えない。

| 処理 | 実行周期（tick） |
|---|---:|
| 命令適用・王・勝敗判定 | 毎tick |
| 移動 | 2 |
| 合流・戦闘 | 2 |
| 建設・破壊・開墾等の作業 | 6 |
| 村人口 | 12 |
| 税収・維持費・自然減少 | 24 |
| 自動判断 | 24 |

既定の順序は `commands → movement → contacts → work → population → economy → ai → leaders → outcome`。1日=6 tick。UIは標準速度で約0.2秒/tick、1×/2×/4×を選べる。停止中や説明モーダル表示中は進行しない。端末の処理負荷で実時間は変わる。

## 人口・領土・出兵

村の周囲8マスにある自国領数を `T` とする。

- 村人口上限 `L = (T + 1) * 16`。
- 現在人口 `P <= L` のとき、`max(1, floor((8 + T) * (40 - tax) / 40))` を加える。
- `P > L` のとき、周囲の中立・柵なし・さら地を1マス領有できれば、出兵せずに領地拡張する。
- 拡張できず、通常部隊数が256未満なら、兵力 `P - 1` の部隊を村のマスに生成して、村人口を1に戻す。
- 出兵時の行動は各国の `initial_order`。自国は「オート」「住居オート」「待機」をUIから選択できる。

`population(team)` はその国の村人口と通常部隊兵力の合計で、王の兵力を含まない。表示の人口もこの定義を使う。

## 資金・税率・消耗

税率は0〜30%。低いほど人口増加が速い。徴税は王が城中央（`home`）にいる、生存している、税率が1%以上、自村まで税路が通る、という条件で行う。税路は通行可能で、所有者が中立または自国、途中の村が自国である経路。敵領・敵村・柵・橋のない水面等で途切れる。

- 各接続村は24 tickごと `max(1, floor(P * tax / 100))` の収入を生む。
- 自村上では兵力2048以上の部隊に維持費 `floor(power / 2048)` がかかる。
- 自村外、または維持費を払えない部隊は、24 tickごと `max(1, floor(power / 80))` を失う。
- 王はこの通常部隊の維持費・自然減少の対象ではない。

## 命令

UIの「村」と「住居」は同じ施設を指す。`build_village` / `destroy_village` は互換用の別名で、命令入力時に `build_base` / `destroy_base` に正規化する。

| action | 内容 | 操作／完了条件 |
|---|---|---|
| move | 移動 | 部隊選択→地点タップ。到着後は待機（手動命令） |
| wait | 待機 | 現在地で停止。自動化も解除 |
| auto | オート | 住居建設と戦力判断を含めて自動運用 |
| develop | 住居オート | 住居建設・必要な開墾を続ける。攻撃しない |
| defend | 拠点防衛 | 指定位置に移動して保持 |
| reinforce | 援軍 | 指定位置に移動し、味方へ合流 |
| build_base | 村建設 | さら地の対象上に立ち、資金100・兵力32を消費。人口32の村を作る |
| destroy_base | 村破壊 | 対象上または直交隣接位置から村を消す |
| reclaim | 開墾 | 荒れ地をさら地・自国領へ変更 |
| build_bridge | 橋建設／修理 | 対象に隣接する陸地から耐久を1増やす |
| destroy_bridge | 橋破壊 | 対象に隣接する陸地から耐久を4減らす。0になるまで継続 |
| build_fence | 柵建設 | 対象に隣接する陸地から耐久4を増やす |
| destroy_fence | 柵破壊 | 対象に隣接する陸地から耐久を4減らす。0になるまで継続 |
| seal_cave | 洞窟封鎖 | 対象に隣接する陸地からさら地・自国領にする |
| tax | 税率変更 | `extra.value` に0〜30を指定。部隊指定は不要 |
| initial_order | 出兵時行動 | `extra.order` に行動を指定。部隊指定は不要 |

王への部隊命令は `move` と `wait` だけがコアで許可される。

村はさら地・柵なし・城以外へ建設可能。同国の村と斜めを含め隣接できない。建設成功時に対象と周囲の柵なし・さら地を自国領にする。自動建設は敵村への上書きを避ける。

橋の初回の耐久1は資金30、建設履歴 `bridge_built=true` がある対象は資金2。橋・柵建設は1回成功すると命令が完了する。柵は資金1で耐久4。橋上、隣の橋上、水面、斜め隣接からは作業しない。到達可能な直交隣接陸地を選び、橋上から破壊を命じられた部隊は先に岸へ移動する。

## 合流・戦闘・王

味方が同じマスに立つと合流し、残った部隊は吸収した兵力を加える。王が常に優先。明示的な援軍の受け手を優先し、そのほかは手動命令、住居オート、援軍受け手、兵力、IDで優先順位を決める。合流後の命令は受け手のものを維持する。

敵同士は同マスまたは直交隣接で戦闘する。城中央の防御係数は王=4、通常部隊=3、それ以外=1。

```text
Aの損害 = min(A兵力, max(1, floor(B兵力 * B係数 / (8 * A係数))))
Bの損害 = min(B兵力, max(1, floor(A兵力 * A係数 / (8 * B係数))))
```

1接触の損害は戦闘前の双方の兵力から同時に算出する。複数接触はID順の走査。王の兵力が0になると国が敗れる。王は城にいると、通常人口を上限に最大16/tick回復する。城内で王の兵力が通常人口の2倍を超えると、部隊上限の範囲で兵力の1/4を通常部隊として分離する（この条件は独自補完C）。

王が敵王を倒した場合、敵の資金・村・部隊・領地を引き継ぐ。別の撃破の場合は敗れた国の村・部隊が消え、土地が中立になる。

## 自動判断

現在のAIは実験用Cの戦略で、原作AIの忠実再現ではない。

1. 不利な敵の防御圏では自村へ集結。
2. 有効な建設・開墾作業は完了まで継続。塞がれた作業は再判断。
3. 既存村・城から6マス以内の、自国または中立の安全な建設場所を選ぶ。到達不能な候補を避け、複数部隊の隣接する予定地を予約で排除する。内政部隊は味方の大軍に吸収されて命令が消えないよう、他の味方がいるマスを避けて移動する。
4. 村数にかかわらず通常オートの一部を内政に割り当て、開発を継続する。7村未満は初期開発を優先し、その後も安全で兵力32超の候補4隊につき1隊（最低1隊、最大3隊、建設資金の範囲）を確保する。作業中の部隊を優先し、残りは小さい部隊から選んで主力軍を残す。住居オートはこの役割数制限を受けない。
5. 建設可能なさら地を開墾より優先。適切なさら地がない場合に近くの荒れ地を開墾する。
6. 住居オートで資源・兵力不足なら自村へ待機し、攻撃へ移行しない。手動命令で解除でき、保存・読込後も継続する。
7. 通常オートは兵力96以上で、防御見積もりの150%以上の兵力がある敵を攻撃候補にする。防御見積もりには周囲3マスの敵部隊・王とその城係数、対象村人口の半分を含める。
8. 攻撃中も24 tickごと再判断する。目的地だけでなく経路の各マスにも戦力条件を適用し、強敵を迂回できなければ攻撃候補から外す。内政・集結部隊は敵の防御圏を避ける。
9. 集結では到達可能な自村のうち敵の脅威が低い村を選び、集結部隊がいる村、前線に近い村、IDの順に優先する。各部隊が最寄りの別々の村で待つ状態を避け、合流して攻勢を再検討する。城へ自動集結して王に全軍を吸収させることも避ける。

王も十分な戦力優位がある場合だけ敵王へ出る。CPU間も互いを敵として扱い、プレイヤーだけを標的にはしない。

## スマホUI

横持ちを基本に、盤面は全画面のControlを使用する。上部はメニュー・再開/停止1ボタン・自国資金/人口・残り日数・税率スライダー。下部は短い選択表示と「全軍」、選択時だけ「待機」「オート」「住居オート」「建設・命令」「解除」を表示する。各国の情報、速度、全景、範囲選択、出兵時行動、保存、読込、記録、説明はメニューに集約する。

- 部隊をタップ→空の目的地をタップで移動。移動ボタンは不要。
- 別の自軍部隊をタップすると選択を切り替える。
- 建設・援軍等を明示的に選んだ場合、その目的地タップを優先。
- 停止中の命令は次の再開時に適用。
- 長押しで詳細。2本指でパン・ピンチ。ジェスチャの離指で移動命令は出さない。
- 全画面は起動時のボタンまたはメニューから要求し、対応ブラウザでは横画面ロックも試みる。ブラウザの権限・対応によりロックできない場合は端末を横にする。
- 縦横切替では盤面と入力の縦横比を保って画面いっぱいに再配置する。ゲームはそのまま継続し、回転によるリセットは行わない。

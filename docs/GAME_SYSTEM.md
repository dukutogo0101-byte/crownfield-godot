# CROWNFIELD ゲームシステム（実装の説明）

更新日: 2026-10-15。共同開発者はこの文書から読み始める。

この文書は `core/simulation.gd`、`data/rulesets/playable_experimental.json`、`ui/game.gd` の**現在の実装**を説明する。原作ロードモナークの確定仕様を主張する文書ではない。原作の調査仕様は `SPEC_CANONICAL_JA.md` と `RULE_STATUS.csv` に分離してある。矛盾があれば実装を確認し、この文書を更新する。`distributions/` の元ZIP・APKは復旧時点の旧版で、最新ソースではない。

## プレイヤーの目的と基本ループ

プレイヤーは青国（team 0）を操作する。村の人口を増やす → 領地を広げる → 部隊を出す → 住居を建設する／味方と合流する → 敵の部隊・村・王へ進軍する、というリアルタイム戦略ゲーム。独自マップは従来の「四つの川（Four Rivers）」と、Grok制作の「開けた野」「二つの渡し」「境界の半島」「継承の地峡」「片海」「渦の水路」「店先の踏切」の8面。開始画面、またはメニューの「マップ選択・新しいゲーム」で選ぶ。選択操作だけでは進行中の世界は置き換わらず、「このマップで開始」で新規ゲームになる。保存・読込とリプレイは選んだマップの初期状態・地形も含む。「もう一度プレイ」は同じ面を再開する。

- 敵3国の王を倒し、自国だけが生存すると勝利。
- 自国の王が倒れると敗北。
- 自国が生存していても600日（3600 tick）で制限時間切れになると敗北。
- 王による敵王の撃破だけが資産接収になる。通常部隊による王撃破では敗れた国の資産は消滅する。

## 地図と初期配置

40 × 26の格子。位置IDは `y * w + x`、座標は0始まり。移動・戦闘接触・橋等の作業位置は上下左右の4方向、村の周囲と村同士の建設間隔は斜めを含む8方向を使う。

| team | 名前 | 操作 | 城の位置ID | 初期資金 | 税率 |
|---|---|---|---:|---:|---:|
| 0 | Azure | プレイヤー | 164 | 800 | 10% |
| 1 | Crimson | CPU | 194 | 800 | 10% |
| 2 | Jade | CPU | 874 | 800 | 10% |
| 3 | Amber | CPU | 844 | 800 | 10% |

表の城の位置は「四つの川」の例で、他の面では配置が異なる。[マップ一覧](MAPS.md)も参照。各国に人口128の村2つ、兵力96の部隊2つ、兵力448の王1人を初期配置する。

| terrain | 地形 | 通行 |
|---:|---|---|
| 0 | さら地 | 柵がなければ通行可能 |
| 1 | 荒れ地 | 柵がなければ通行可能。開墾で0になる |
| 2 | 水面 | 橋耐久が1以上で通行可能 |
| 3 | 洞窟 | 通行不可。封鎖で0になる |

所有者 `owner` は中立=-1、国=0〜3。歩兵がさら地へ移動すると、そのマスの所有者が自国になる。敵村へ進入すると村を破壊する。柵があるマスは橋の有無にかかわらず通行できない。

## 時間と処理順

整数tickで決定論的に進行する。乱数は現在使用していない。UIの速度や実時間はコアの計算式を変えない。

| 処理 | 実行周期（tick） |
|---|---:|
| 命令適用・王・勝敗判定 | 毎tick |
| 移動 | 2 |
| 合流・戦闘 | 2 |
| 建設・破壊・開墾等の作業 | 6 |
| 村人口 | 12 |
| 税の積算 | 毎tick |
| 徴収・維持費・自然減少 | 24 |
| 自動判断 | 24 |

既定の順序は `commands → movement → contacts → work → population → economy → ai → leaders → outcome`。1日=6 tick。UIは標準速度で約0.2秒/tick、1×/2×/4×を選べる。停止中や説明モーダル表示中は進行しない。端末の処理負荷で実時間は変わる。

## 人口・領土・出兵

村の周囲8マスにある自国領数を `T` とする。

- 村人口上限 `L = (T + 1) * 16`。
- 現在人口 `P <= L` のとき、`max(1, floor((8 + T) * (40 - tax) / 40))` を加える。
- `P > L` のとき、周囲の中立・柵なし・さら地を1マス領有できれば、出兵せずに領地拡張する。
- 拡張できず、通常部隊数が256未満なら、兵力 `P - 1` の部隊を村のマスに生成して、村人口を1に戻す。
- 出兵時の行動は各国の `initial_order`。自国は「オート」「住居オート」「待機」をUIから選択できる。

`population(team)` はその国の村人口と通常部隊兵力の合計で、王の兵力を含まない。表示の人口もこの定義を使う。

## 資金・税率・消耗

税率は0〜30%。低いほど人口増加が速い。徴税は王が城中央（`home`）にいる、生存している、税率が1%以上、自村まで税路が通る、という条件で行う。税路は通行可能で、所有者が中立または自国、途中の村が自国である経路。敵領・敵村・柵・橋のない水面等で途切れる。

- 接続中の各村は毎tick `tax_credit += P * tax` を積算する。24 tickごと `floor(tax_credit / 2400)` を資金へ移し、端数は次回へ持ち越す。接続していても税率0%なら新たな積算は0。徴収時だけの人口で計算しないため、直前の出兵で期間中の税収が消えることはない。最低1の税収補正は廃止した。
- 王の外出・経路断絶中は積算も徴収も停止する。既に積算した額は保持し、再接続後に徴収する。税率0%へ変えても変更前に積算した税は次回に受け取る。
- 上部の税率ボタンから、接続村数・現在人口での期間税収・次回徴収の目安・人口増加・停止理由を確認できる。概算は出兵・建設・維持費や今後の経路変化を含まない。スライダー操作は次tickに反映され、停止中は予約する。
- 自村上では兵力2048以上の部隊に維持費 `floor(power / 2048)` がかかる。
- 自村外、または維持費を払えない部隊は、24 tickごと `max(1, floor(power / 80))` を失う。
- 王はこの通常部隊の維持費・自然減少の対象ではない。

## 命令

UIの「村」と「住居」は同じ施設を指す。`build_village` / `destroy_village` は互換用の別名で、命令入力時に `build_base` / `destroy_base` に正規化する。

| action | 内容 | 操作／完了条件 |
|---|---|---|
| move | 移動 | 部隊選択→地点タップ。到着後は待機（手動命令） |
| wait | 待機 | 現在地で停止。自動化も解除 |
| auto | オート | 住居建設と戦力判断を含めて自動運用 |
| develop | 住居オート | 住居建設・必要な開墾を続ける。攻撃しない |
| defend | 拠点防衛 | 指定位置に移動して保持 |
| reinforce | 援軍 | 指定位置に移動し、味方へ合流 |
| build_base | 村建設 | さら地の対象上に立ち、資金100・兵力32を消費。人口32の村を作る |
| destroy_base | 村破壊 | 対象上または直交隣接位置から村を消す |
| reclaim | 開墾 | 荒れ地をさら地・自国領へ変更 |
| build_bridge | 橋建設／修理 | 対象に隣接する陸地から耐久を1増やす |
| destroy_bridge | 橋破壊 | 対象に隣接する陸地から耐久を4減らす。0になるまで継続 |
| build_fence | 柵建設 | 対象に隣接する陸地から耐久4を増やす |
| destroy_fence | 柵破壊 | 対象に隣接する陸地から耐久を4減らす。0になるまで継続 |
| seal_cave | 洞窟封鎖 | 対象に隣接する陸地からさら地・自国領にする |
| tax | 税率変更 | `extra.value` に0〜30を指定。部隊指定は不要 |
| initial_order | 出兵時行動 | `extra.order` に行動を指定。部隊指定は不要 |

王への部隊命令は `move` と `wait` だけがコアで許可される。

村はさら地・柵なし・城以外へ建設可能。同国の村と斜めを含め隣接できない。建設成功時に対象と周囲の柵なし・さら地を自国領にする。自動建設は敵村への上書きを避ける。

橋の初回の耐久1は資金30、建設履歴 `bridge_built=true` がある対象は資金2。橋・柵建設は1回成功すると命令が完了する。柵は資金1で耐久4。橋上、隣の橋上、水面、斜め隣接からは作業しない。到達可能な直交隣接陸地を選び、橋上から破壊を命じられた部隊は先に岸へ移動する。

## 合流・戦闘・王

味方が同じマスに立つと合流し、残った部隊は吸収した兵力を加える。王が常に優先。明示的な援軍の受け手を優先し、そのほかは手動命令、住居オート、進行中の工兵作業、援軍受け手、兵力、IDで優先順位を決める。合流後の命令は受け手のものを維持する。

敵同士は同マスまたは直交隣接で戦闘する。城中央の防御係数は王=4、通常部隊=3、それ以外=1。

```text
Aの損害 = min(A兵力, max(1, floor(B兵力 * B係数 / (8 * A係数))))
Bの損害 = min(B兵力, max(1, floor(A兵力 * A係数 / (8 * B係数))))
```

1接触の損害は戦闘前の双方の兵力から同時に算出する。複数接触はID順の走査。王の兵力が0になると国が敗れる。王は城にいると、通常人口を上限に最大16/tick回復する。城内で王の兵力が通常人口の2倍を超えると、部隊上限の範囲で兵力の1/4を通常部隊として分離する（この条件は独自補完C）。

王が敵王を倒した場合、敵の資金・村・部隊・領地を引き継ぐ。別の撃破の場合は敗れた国の村・部隊が消え、土地が中立になる。

## 自動判断

現在のAIは実験用Cの戦略で、原作AIの忠実再現ではない。

AIは `core/strategic_ai.gd` で命令を計画し、移動・合流・戦闘・費用・作業を全て共通のsimulationで実行する。資金や兵力の付与、専用の架橋速度、障害物を無視する移動はない。現時点では地図と全軍の情報を参照し、視界制限・偵察のルールはない。

1. **継続する内政**：7村は初期優先目標であり上限ではない。安全な通常オート候補の4隊に1隊、最大3隊を内政に配分し、初期は拡張を優先する。作業中・小さい部隊を優先し、住居オートの部隊はこの配分に算入する。進行中の工兵は内政へ転用しない。
2. **住居の連続建設**：自村・城から6マス以内の安全な中立／自国地を使う。複数の建設地を予約し、味方軍との合流で作業が失われる経路を避ける。建設可能地を開墾より優先。完成時に次の作業をすぐ計画し、実際の移動・作業周期と費用は守る。明示的な住居オートは戦闘へ切り替えない。
3. **集結と退避**：小部隊は共通の安全な自村へ合流する。強敵の防御圏内では、敵との隣接が増えず、危険と距離の費用が小さい退路を探索する。防御圏を一切通れない従来の経路だけに頼って停止することを避ける。包囲されて安全な経路がない場合は無理に敵へ進まない。
4. **防衛**：城から8マス以内、または自村から4マス以内の侵入者を評価する。優勢な部隊で迎撃し、城近くで劣勢なら守備へ戻す。非常に強い侵入者には、橋の切断・狭路の柵も検討する。自国の村や部隊を対岸に取り残す遮断は行わず、遮断地点を240 tickは攻撃路として開け直さない。
5. **攻撃目標**：最低兵力96、防御見積もりの150%以上を条件にする。周囲3マスの敵と城倍率、村人口の半分を含める。目標価値、経路距離、橋・柵等の費用と作業時間を比較し、同じ目標への小さい継続加点で頻繁な行き先変更を抑える。各マスの安全性も調べ、進軍中も再確認する。敵同士も対等に交戦する。
6. **経路の整備**：攻撃路や切れた税路の架橋、既設橋の修理、柵破壊、洞窟封鎖を計画する。主力以外の部隊を工兵に優先し、安全な岸へ到達できるときだけ作業する。橋の目標耐久は4で、1点ごとに通常の30／2資金と6 tickの作業を支払う。完了した修理は定期判断を待たず次の1点を命令する。主力が別なら岸へ護衛し、完成後に攻撃を再判断する。資金不足や危険化した計画は取り消す。
7. **公平な地形制約**：工兵も対象と直交隣接する陸地からしか作業しない。2マス以上の幅の川は、対岸への別の既設経路等がないと橋を完成できない。計画時もこの制約を守り、不可能な架橋に資金を使わない。敵は必要性のある作業を選ぶため、全種類の命令を常に使うわけではない。
8. **税と王**：CPUは資金100未満なら25%、建設予備費未満なら20%、余剰が多ければ5%、その他は10%へ調整する。予備費は `max(300, 村数×12)`、変更間隔は120 tick。自国の税率は変更しない。CPU王は基本的に徴税・守備のため城へ留まり、外にいれば戻る。近くの敵王を安全に倒せる場合は出撃を検討する。

メニュー「各国の状況」で、その国の現在の内政・集結・防衛・経路整備・攻勢方針を確認できる。手動命令は自動計画より優先する。判断や作業の意図は保存される。

## スマホUI

横持ちを基本に、盤面は全画面のControlを使用する。上部はメニュー・再開/停止1ボタン・自国資金/人口・残り日数・税率ボタンとスライダー。下部は短い選択表示と「全軍」、選択時だけ「待機」「オート」「住居オート」「建設・命令」「解除」を表示する。各国の情報、速度、全景、範囲選択、出兵時行動、保存、読込、記録、説明はメニューに集約する。

- 部隊をタップ→空の目的地をタップで移動。移動ボタンは不要。
- 別の自軍部隊をタップすると選択を切り替える。
- 建設・援軍等を明示的に選んだ場合、その目的地タップを優先。
- 停止中の命令は次の再開時に適用。
- 長押しで詳細。2本指でパン・ピンチ。ジェスチャの離指で移動命令は出さない。
- 全画面は起動時のボタンまたはメニューから要求し、対応ブラウザでは横画面ロックも試みる。ブラウザの権限・対応によりロックできない場合は端末を横にする。
- 縦横切替では盤面と入力の縦横比を保って画面いっぱいに再配置する。ゲームはそのまま継続し、回転によるリセットは行わない。

## 未実装・検証の区別

複数面キャンペーン、同盟、洞窟からの魔物生成、原作と同じAI・戦闘・経済式、クラウドセーブ、マルチプレイは未実装。`score(team)` は存在するが、現在の終了画面の `state.score` との接続は未完成。原作素材は使用しない。

Godot内のヘッドレステストとWeb出力・JavaScriptの静的／ローダー検証を実施する。実際のAndroid/iPhoneブラウザでの表示・操作・オフライン動作は別途確認が必要。

## 動作の軽量化と移動表示

ゲームの論理位置・移動周期・戦闘・税率は従来どおり。部隊の見た目だけを前後のマス間で補間する。選択は表示位置から行え、建設先は盤面のマスで指定する。一時停止・モーダル中は補間も止まり、読込・再開始では前の移動を引き継がない。遅いフレームやタブ復帰時は1フレームの追いつき処理を最大2 tick、目安6msの処理枠に制限する。重い場面では実時間の進行が遅くなることがあるが、論理tickや命令を飛ばすことはない。


## クリア記録（2026-10-17）

青国が勝利すると、マップ別のクリア回数・最短クリア日数・直近のクリア日時を自動保存する。☰の「クリア記録」から全8面の一覧を開ける。マップ選択のクリア済み面にはチェックが付き、選択面の記録も表示する。最短日数は論理tick÷day_ticksで比較し、小数1桁で表示する。速度変更や一時停止の現実時間は含まない。

記録は端末内。Web版は同じサイトのlocalStorageキー `crownfield.clear_records.v1`、ネイティブ版は `user://crownfield_clears.json` を使用する。サイト更新・新しいゲーム・進行セーブの読込では消えないが、ブラウザのサイトデータ削除や別ブラウザ／端末とは共有しない。ブラウザが保存を拒否した場合は勝利画面に失敗を表示する。進行セーブのJSONはクリア一覧のバックアップではない。

`run_id` を新規ゲームごとに発行し、進行セーブとJSON出力にも保持。同じゲームを読込・再インポートしても1回だけ加算する。再挑戦は新しいID。リプレイ再生とそれを保存・読込した状態は `record_eligible=false` で加算しない。旧セーブはreplay_originの状態ハッシュから同じIDを再生成するため、同じ初期状態しか残っていない複数の旧ゲームは区別できない。過去の記録は自動復元しないが、勝利状態の保存が残っていれば読込時に記録できる。

記録はシミュレーションのsnapshot・checksum・リプレイの決定論から独立している。ネイティブ書込は一時ファイルを完了してから置換し、有効な前回ファイルを `.bak` に残す。破損時は検証できるバックアップを復元し、復旧不能の既存ファイルは自動上書きしない。オンラインランキングや不正対策の機能ではない。


### フーズパニックの見た目

「店先の踏切」は原作のフーズパニックを参照した専用スキン。自店は赤のウィバーガー。画面では舗装地・線路・踏切・店舗・配達員・店長として表示する。命令名は「新装開店」「店じまい」「出店オート」などに切り替わる。内部のteam 0、terrain、村・王・部隊、建設費と税の仕組みは上記の共通ルールを使う。ほかの7面では従来の表示を使う。描画素材は46タイルの新規SVGで、同じIDの旧セーブとクリア記録を引き続き利用できる。

# Grok向け：マップ開発の依頼と仕様

## 担当範囲

Grokは新規マップの地形・初期配置・難易度・試遊結果を担当する。Codexはシミュレーション、AI、操作、保存、Web公開を担当する。

正本は https://github.com/dukutogo0101-byte/crownfield-godot 。必ず最新mainの `docs/GAME_SYSTEM.md`、`docs/DEVELOPMENT.md`、`data/maps/four_rivers.json` を読む。

`grok/maps` など専用ブランチで、新規 `data/maps/*.json`、新規 `tests/map_*.gd`、新規 `docs/maps/*.md` を作る。既存four_rivers、core、ui、web、project.godot、ルールJSON、goldenには変更を加えない。既存マップやgoldenの上書きではなく、追加として提出する。マップ選択画面と公開版への統合はCodex側で行う。

## 最初に作る3枚

最初は現行と同じ40×26マスを基本にする。

| ID案 | 内容 | 検証する遊び |
|---|---|---|
| open_plains | 平地が広く、初期の脅威が小さい入門面 | 村を増やす・兵を集める基本 |
| twin_crossings | 川と既設の橋があり、各国に複数の進軍路がある面 | 橋の防衛、迂回、前線選択 |
| borderlands | 半島・荒れ地・中央の争奪地がある標準面 | 安全な内政地と攻勢の配分 |

現在の敵AIは村建設と開墾を自動で行うが、橋建設・洞窟封鎖を自動では計画しない。島や川を使う場合は必要な橋をあらかじめ設置し、最初から4か国の城を相互に到達可能にする。必須の橋建設や洞窟封鎖を敵に要求する面は、別途エンジン対応が必要なので今回の範囲外とする。

## JSON契約

新規ゲームの入力ファイルはセーブファイルとは異なる。`snapshot`や`checksum`を包まず、既存four_riversと同じトップレベルを持つJSONにする。

| 項目 | 契約 |
|---|---|
| id / name / version | 重複しない文字列ID、日本語の面名、整数版番号 |
| w / h | マップ幅・高さ。推奨40×26。位置は `pos = y * w + x`、左上0 |
| cells | 要素数がちょうどw×hの配列 |
| factions | ID 0〜3の順に4国。0はプレイヤー |
| bases / units / leaders | それぞれ村・通常部隊・王の配列。全配列を通じてIDを一意にする |
| next_id | 使用済みの全IDより大きい整数 |

各cellは `terrain`（0=建設可能な平地、1=開墾できる荒れ地、2=水、3=洞窟）、`owner`（-1=中立、0〜3=所属国）、`bridge`（非負の耐久整数）、`bridge_built`（bool）、`fence`（非負の耐久整数）を持つ。水はbridge>0の場合だけ通れる。柵や洞窟は通れない。

各factionは `id,name,funds,tax,home,alive,initial_order` を持つ。資金・税率・位置は整数、aliveはbool。通常は初期命令auto。王は各国1人で `id,team,pos,power,order,target,manual,king` を持ち、king=true、初期位置はその国のhomeとする。aliveはnew_gameで追加される。

村は `id,team,pos,pop`、通常部隊は `id,team,pos,power,order,target,manual,king`（king=false）を持つ。初期のauto_modeやAI補助フィールドはエンジンが設定する。初期値は既存面を基準にし、地形の面白さと数値による難易度変更を同時に大きく変えない。

## 制作時の確認

- 初期配置は通行可能な陸地に置き、城と村・部隊の不正な重複を避ける。同国の村は縦横斜めの隣接マスに置かない。
- 城と初期村の税路を、自国の通れる領地で接続する。川や中立地で初期から税収が止まる配置を避ける。
- 各国に十分な安全な内政地を確保する。目安は20村以上の建設候補だが、村同士の隣接制限と到達性を考慮して数える。
- 敵同士も戦うため、プレイヤーだけを狙う前提で配置しない。初期兵が一方的に挟撃される配置、城の目の前で即戦闘になる配置を確認する。
- 4方向移動を前提に経路を確認する。見た目では接していても、斜めだけの接続は通行路にならない。
- 全要素をJSONの整数・boolで保持し、小数の位置・資金・兵力を入れない。

## 検証と提出物

Godot 4.5.2で `Core.new().new_game("res://data/maps/<id>.json")` を使って起動する。現行UIの新規ゲームはまだfour_rivers固定であり、JSONを追加するだけでは選択肢には出ない。

新規テストでは、`restore(sim.snapshot())`の成功、全城間の到達性、初期村の税収条件、初期拠点の近接違反なしを確認する。新規ゲームを少なくとも1200 tick進めて、国別の村数・人口・生存・資金を記録する。勝敗や国の脱落はゲームの結果として扱い、単に全員が生存していることを合格基準にしない。安全な空き地があるのに開発できない国、通路で永久停止する部隊を調べる。

各面のJSON、配置意図と難易度、テスト方法と結果、未検証事項をPRにまとめる。新しい建物・資源・地形効果など、エンジンがまだ実装していない要素をJSONへ足して実装済みの扱いにしない。

# カクつきの軽減（2026-10-15）

AI判断・税路・移動経路・建設予約の重複計算と、マス単位で瞬間移動する表示を改善した。敵の判断周期や戦闘・移動・人口・税収のルールは変更していない。元のAPK・復旧用ZIPは旧版のまま。

## 実施した変更

- 経路探索はマップの隣接リストを再利用する。Dijkstraの進入費用は各マス1回だけ評価し、退避中は目標までの探索で止める。
- 同じ集結先へ移動する多数の部隊は距離場を共有する。上・左・右・下の選択順と最短経路は維持する。少数の場合は短い通常探索を使う。
- AIは安全な連結領域を国ごとに再利用する。建設予定地の周囲を先に予約集合へまとめ、全候補から同じ近隣判定を何度も行わない。開発範囲の判定も距離場に置き換える。
- 税路は、全セルの通行可能性・所属、村の位置と所属、地図寸法、探索順を正確に比較し、変化した場合に更新する。王の位置・生存・城の条件も確認する。単なるハッシュ一致には頼らない。表示の税収見込みもこの経路を使う。
- 状態ハッシュ用のJSONはGodot標準の再帰キーソートを使う。旧シリアライズと同じ文字列になり、golden・保存チェックサムを維持する。
- 地形・村、動く部隊、ミニマップのCanvasItemを分離する。部隊の補間フレームでは地形を再描画しない。ミニマップは地形・所属が変わるときに画像を更新する。画面外の地形と部隊の処理も減らす。
- 移動表示は前後のマス間で補間する。論理位置は変更しない。タップは見えている部隊の位置から選択でき、建設先指定は本来のマス座標を使う。停止・モーダルで補間も止め、読込・再開始で過去の移動を破棄する。
- 長いフレームやブラウザのタブ復帰で最大20 tickを一度に処理していた追いつきループを、最大2 tick・約6msの目安へ制限する。1 tick自体を途中で中断するものではない。端末負荷が高い場合は実時間の進行が遅くなるが、論理tickや命令を飛ばさない。

派生キャッシュと表示補間は保存データ、状態ハッシュ、ゲームのルールへ入れない。

## 同一条件での計測

変更前はコミット `beb6737de5a5941180fbaaf3d2c6bc6ebd90e4e3`。Godot 4.5.2 stable、Linuxのネイティブ・ヘッドレスで、同じ初期状態から120 tickずつ各3回。変更前後は順番に実行した。多数部隊のケースは `tests/fixtures/pre_ai_fix_stalemate.json` を復元し、120 tick後に61部隊・82村になる。

| ケース | 変更前 平均/tick | 変更後 平均/tick | 変更前 最大/tick | 変更後 最大/tick |
|---|---:|---:|---:|---:|
| 序盤 | 18.25ms | 5.05ms | 167.24ms | 63.14ms |
| 多数部隊 | 28.15ms | 14.15ms | 336.38ms | 133.48ms |

多数部隊の平均を約50%、最大を約60%削減した。このケースのAI判断があるtickの平均は239.08ms→108.55ms。状態ハッシュ処理の平均は8.44ms→3.09ms。

これはCPU処理時間であり、AndroidブラウザのFPSやGPU描画時間ではない。重い単一tickによる引っ掛かりが完全になくなる保証はなく、スマホ実機・ブラウザ実操作は未検証。静止画の見栄えやGPU性能の実機評価も別途必要。

計測の生データは `tests/performance_benchmark_results.json`。同じスクリプトを変更前と変更後のcheckoutに対して実行する。

```bash
godot --headless --path /path/to/before --script /path/to/after/tests/performance_benchmark.gd -- /tmp/before.json
godot --headless --path /path/to/after --script /path/to/after/tests/performance_benchmark.gd -- /tmp/after.json
```
